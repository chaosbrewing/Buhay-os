# HANAY handoff, 2026-11-21

For whoever picks this project up next (a person or another coding agent). It says what exists, where it runs, how to change and deploy it, what was proved, and what is still open. It contains no secrets: variable names only. Read `docs/release-hardening-2026-11-21.md` for the evidence and `docs/HANAY_Brand_and_Migration_Specification_v0.1.md` for the rename.

## 1. What this is

HANAY (formerly BUHAY.OS) is a private life planner. Planner data is encrypted in the browser with the user's passphrase before it is sent anywhere; the server stores only ciphertext. A lost passphrase cannot be recovered, by design.

- Visual wordmark `hanay.`; tagline "Make room for life."; design system ORIGIN Glass (Daylight and Midnight themes).
- Internal feature names kept on purpose: BAKAS (memories), TUKLAS (finances), UGNAY (links). IKAW is not in the code.
- Monorepo (pnpm): `artifacts/life-planner` (web, Vite/React/TS), `artifacts/api-server` (Express 5 + Clerk), `artifacts/buhay-os-mobile` (Expo, on hold), `artifacts/buhay-os-daybook-film`, `artifacts/mockup-sandbox`, `lib/planner-contract` (shared data rules), `lib/api-zod`, `lib/api-client-react`, `lib/api-spec`, `lib/db` (Drizzle).

## 3. Environment variables (names only)

| Variable | Used by | Set where |
|---|---|---|
| `DATABASE_URL` | API | Vercel (production); local from `neon env pull` into `.env.local` |
| `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` | API | Vercel (production, live keys) |
| `SESSION_SECRET` | API (Google OAuth state and token encryption) | Vercel. Changing it invalidates stored Google connections. |
| `CORS_ALLOWED_ORIGINS` | API | Vercel: `https://hanay.today` |
| `NODE_ENV` | API | Vercel: `production` |
| `GOOGLE_CALENDAR_CLIENT_ID`, `GOOGLE_CALENDAR_CLIENT_SECRET`, optional `GOOGLE_CALENDAR_REDIRECT_URI` | API | **Not set.** Calendar sync is untested and should stay off until set. |
| `VITE_CLERK_PUBLISHABLE_KEY` | Web, baked in at build | Root `.env.local` (live key) for production builds; `artifacts/life-planner/.env.development.local` (test key) for local runs |
| `VITE_API_URL` | Web | `/api` |
| `PORT`, `BASE_PATH` | Web build and dev (required) | Set in the shell; use `BASE_PATH=/` |
| `VITE_JOURNAL`, `VITE_TUKLAS`, `VITE_BAKAS_MEMORIES`, `VITE_RELEASE_TWO_*` | Web feature flags, build time | All off in the live build (`"false"` in `.replit`). They fail closed (`=== 'true'`). |

Local `.env*` files are gitignored. Vercel stores the production secrets as hidden values. `vercel link` also wrote a `VERCEL_OIDC_TOKEN` into the root `.env.local`; it is ignored by git.

## 4. Run it locally

```
pnpm install --frozen-lockfile
# web (needs a test Clerk key in artifacts/life-planner/.env.development.local)
cd artifacts/life-planner && PORT=5190 BASE_PATH=/ pnpm run dev
# API (needs DATABASE_URL, Clerk test keys, SESSION_SECRET, CORS_ALLOWED_ORIGINS, PORT, NODE_ENV=development)
cd artifacts/api-server && node build.mjs && node dist/index.mjs
```

The Vite dev server has no `/api` proxy; use the Worker path in production, or add a local proxy (not committed).

## 5. Test it

- Typecheck: `pnpm run typecheck` (if it fails strangely, delete `artifacts/*/tsconfig.tsbuildinfo` and `lib/*/tsconfig.tsbuildinfo`; a stale cache once reported a false zod error).
- Unit tests: `lib/planner-contract` (130), `artifacts/life-planner` (137), `artifacts/buhay-os-mobile` (41), `artifacts/api-server` (62).
- Browser suites in `artifacts/life-planner` (`pnpm run test:e2e:<name>`): journal, tuklas, planner, memory, backup, calendar, release-two, recurrence, a11y. `habits` needs a Clerk key and is not run in CI.
- Ops checks (`scripts/ops/`): `isolation-test.mjs` (two throwaway Clerk dev users against a local API and the Neon `development` branch; 13 checks) and `restore-drill.mjs` (temporary Neon branch, delete, point-in-time restore, decrypt check).
- CI (`.github/workflows/ci.yml`) runs typecheck, unit tests, production builds, an audit report and the browser suites on every push and pull request. It was green on the last merge.

## 6. Deploy it (manual)

Nothing deploys on a git push.

1. **API:** from the repo root, `node artifacts/api-server/build-vercel.mjs`, then `npx vercel@latest deploy --prebuilt --prod --yes`. Needs `vercel login` (browser device approval).
2. **Web and Worker:** in `artifacts/life-planner`, build with `PORT=5199`, `BASE_PATH=/`, `NODE_ENV=production`, `VITE_API_URL=/api` and the live `VITE_CLERK_PUBLISHABLE_KEY`, then `npx wrangler@latest deploy`. Needs `wrangler login`.
3. Check: `/` and `/sign-in` return 200, `/api/healthz` 200, `/api/planner` 401 without a login, `www` returns 301 to the apex.
4. **Rollback:** Vercel and Cloudflare both keep earlier versions; redeploy or roll back the previous one in their dashboards. The data schema has not changed, so a code rollback does not touch stored data.

## 7. Security posture (summary)

## 9. Gotchas

- **Windows:** the Clerk CLI (a Bun program) crashes with "Illegal instruction" on the development machine. Use the Clerk dashboard. Several Playwright configs set environment variables POSIX-style; CI is Linux, so they work there. Locally, run temporary copies that use `env: {PORT, BASE_PATH}`. Git Bash mangles `BASE_PATH=/`; use PowerShell for that variable. The API `test` script is POSIX-only; run its steps directly on Windows.
- **Wrangler** finds its saved sign-in from Bash but not from the PowerShell tool.
- **pnpm** refuses packages published in the last day (`minimumReleaseAge`). Adding a dependency can pull a second copy of a library and break type checks; check `pnpm-lock.yaml` after any install.
- **Drizzle push on Windows:** `lib/db/drizzle.config.ts` builds the schema path with backslashes, which drizzle-kit cannot match. Use a throwaway config with forward slashes.
- **Preserved identifiers.** Do not rename these without a verified migration; `src/rebrand-compat.test.mjs` pins them: the backup format `buhay-os-encrypted-backup` (bound into the AES-GCM header, so renaming makes old backups unreadable), the `.buhaybackup` extension, `daybook.*` and `buhay.*` storage keys, the Google Calendar request key `buhayOsRequestKey`, `buhay-event-*` and `buhay-task-*` ids, the mobile slug, scheme and package names, and the `/buhay-os-*/` deployment paths.
- **Contract rules** (BAKAS, Journal, TUKLAS): new snapshot fields are optional and absent until used; deletions are content-free tombstones; on merge a tombstone wins, otherwise the newest `updatedAt` wins; validation errors never echo user text. Backup restore passes through `keepDeletedRecords`.
- **Generated files:** `artifacts/mockup-sandbox/src/.generated/mockup-components.ts` shows as modified after any build (line endings only). Restore it with `git checkout`.
- An untracked `HANAY-HARDENING-001.ps1` sits in the repo root; it was not created by this work and was left alone.
