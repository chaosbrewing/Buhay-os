# Buhay.OS

A private, end-to-end encrypted life planner: daily and weekly plans, projects, Inbox capture, habits, routines, notes, templates and Google Calendar, with encrypted sync between the web app and an Expo companion.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev`: build and run the API server (port 8080, served under `/api`).
- `pnpm --filter @workspace/life-planner run dev`: run the web planner (the artifact manifest supplies `PORT` and `BASE_PATH`).
- `pnpm run typecheck`: build the shared library declarations (`typecheck:libs`), then typecheck every app.
- `pnpm run build`: typecheck, then build all packages.
- `pnpm --filter <package> run test`: unit tests (`node --test`) for `@workspace/api-server`, `@workspace/life-planner`, `@workspace/planner-contract` and `@workspace/buhay-os-mobile`. Browser suites are `test:e2e:*` in `artifacts/life-planner` (see its README).
- `pnpm --filter @workspace/api-spec run codegen`: regenerate the React Query client and Zod schemas from `lib/api-spec/openapi.yaml`.
- `pnpm --filter @workspace/db run push`: push the DB schema (dev only). No migration files exist.
- Required server env: `DATABASE_URL`, `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `SESSION_SECRET`, `GOOGLE_CALENDAR_CLIENT_ID`, `GOOGLE_CALENDAR_CLIENT_SECRET` (optional `GOOGLE_CALENDAR_REDIRECT_URI`).

## Stack

- pnpm workspaces (catalog versions in `pnpm-workspace.yaml`), Node.js 24, TypeScript 5.9.
- API: Express 5, Clerk auth, pino logging; bundled with esbuild as ESM (`artifacts/api-server/build.mjs`).
- DB: PostgreSQL + Drizzle ORM.
- Web: React 19 + Vite, wouter routing, TanStack Query.
- Mobile: Expo 57 / React Native 0.86 (on hold except device alarms).
- Validation: Zod 3 (pinned for Orval); API client and schemas generated by Orval.

## Where things live

- `artifacts/life-planner`: the web planner (primary delivery target). `docs/release-2.md` and `docs/web-launch-remediation.md` hold the release gates and evidence.
- `artifacts/api-server`: the API (`src/routes/planner.ts` encrypted state and history; `src/routes/calendar*.ts` Google Calendar).
- `artifacts/buhay-os-mobile`: the Expo companion (`ALARMS.md`, `DEVICE-QA.md`).
- `lib/planner-contract`: the planner data model, merges, recurrence, habits, routines and Release 2 (`src/index.ts`, `src/release2*.ts`). It is the source of truth for snapshot shape.
- `lib/db/src/schema`: DB tables (`planner_state`, `planner_versions`, `google_calendar_connections`).
- `lib/api-spec/openapi.yaml` → `lib/api-client-react`, `lib/api-zod`: API contract and generated code.
- `artifacts/buhay-os-daybook-film`: a promotional brand film, not product. `artifacts/mockup-sandbox`: design preview tooling, not deployed.

## Architecture decisions

- Planner content is end-to-end encrypted in the client (PBKDF2-SHA256 310k, AES-GCM-256). The server stores only the ciphertext envelope plus revisions, and never sees the passphrase.
- New planner fields are optional and additive. Unknown fields are preserved, and older snapshots load unchanged.
- Google Calendar data stays outside the encrypted snapshot. Events are fetched through the API and never stored. Tokens are encrypted server-side.
- Release 2 areas sit behind `VITE_RELEASE_TWO_*` flags (all `false` in `.replit`). Anything rendered without explicit flags fails closed.
- Inbox plan drafts (UGNAY, `lib/planner-contract/src/ugnay.ts`) are behind `VITE_UGNAY_PLAN_DRAFTS` (`false` in `.replit`, on only when exactly `true`). A draft lives in the encrypted snapshot and changes the planner only when the user presses "Add to my planner" on an item. It carries no AI and makes no network calls.
- Offline merges are timestamp- and tombstone-based. Divergent copies without a shared baseline are kept, not guessed.

## Product

The primary journey is sign in → unlock with the planner passphrase → plan and capture → encrypted save → return or recover. Phone navigation: Today / Planner / Capture / Review / You. Desktop navigation uses grouped, collapsible sections.

## User preferences

Recorded decisions are in `.agents/memory/` (index: `MEMORY.md`): E2E encryption, web-first scope, alarms, navigation, branding and routine-run history. Implementation steps need explicit founder approval as YES/NO decisions.

## Gotchas

- Run `pnpm run typecheck:libs` before typechecking an app on its own; stale declaration output makes workspace exports look missing.
- Web unit tests preload `src/test-timezone.mjs` (`Pacific/Kiritimati`). Don't rely on a shell `TZ=` prefix; it doesn't work on Windows.
- API route tests that import workspace TypeScript must be bundled with esbuild first (see the `test` script).
- Keep Expo Router `Stack.Screen` entries as direct children; a fragment crashes the web preview.
- Some binary assets (logo, film media, mobile icons) weren't importable from Replit. See `REPLIT-IMPORT.md`.
